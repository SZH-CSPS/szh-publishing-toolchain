# Use the accessible name of links for /Contents and /Alt

Related to #2550 and #2482 ("Support `aria-*` attributes").

## Problem

With `pdf/ua-1`, the `/Contents` entry of a link annotation is always the link target: the URL, or the anchor name for internal links (`note`, `call`). The link text, `aria-label` and `title` are never used. For an icon link without text (ORCID, licence badge, back link of a footnote), the target is the only name available, and the `/Link` structure element only contains the `/OBJR` reference: assistive technologies, which read the structure tree, have nothing to announce.

```html
<html lang="en">
<style>a.icon { display: inline-block; width: 4mm; height: 4mm; background: #a6ce39 }</style>
<p id="call">See the note<a href="#note">1</a>.</p>
<p><a class="icon" href="https://orcid.org/0000-0002-1825-0097" aria-label="ORCID profile of Jane Doe"></a>
<a class="icon" href="https://creativecommons.org/licenses/by/4.0/" title="CC BY 4.0"></a></p>
<p id="note">1. A footnote. <a class="icon" href="#call" aria-label="Back to the call"></a></p>
```

veraPDF passes, as it only checks that `/Contents` is present.

## Fix

All changes are in `pdf/tags.py`.

- `add_tags()` names link annotations before building the tree, when the boxes of all pages are known. It walks through the boxes and, for each element, it records whether it has a box, a visible box (`visibility: visible`), a block box, or whether it is a footnote. The name of a link is the first non-empty value among `aria-label`, its text, the `alt` text of its images (the `<title>` of inline SVG) and `title`, with normalized spaces. The text is the text of the DOM without what is not displayed (`display: none`, `visibility: hidden`, scripts, comments) and without the body of footnotes called in the link; blocks are separated by spaces. `/Contents` gets this name, and still gets the target when the link has no name at all. Images and pseudo-elements in a link have their own link annotation: they get the name of the link. This follows what `_get_human_name()` already does for form fields.
- `_build_box_tree()`: the `/Link` structure element of an `<a>` named by `aria-label`, or without text, gets the same name as `/Alt`. A link with text and no `aria-label` keeps its text as content and gets no `/Alt`, as in the HTML accessible name computation where `aria-label` overrides the content. `/Alt` is only set on the `/Link` element of the `<a>` itself, never on a `/Figure`, a pseudo-element or an element that already has `/Alt`, and never with the link target: an image without alternative text in a link stays a `/Figure` without `/Alt`, reported by veraPDF (7.3-1), instead of getting its URL as description.

`anchors.py` is not changed: `add_links()` only knows the boxes of one page, and footnotes or hidden content can't be excluded there.

Not covered: `aria-labelledby`, and text generated by CSS (`::before`, `::after`), which is not in the DOM. Links whose text is in a child element are still not tagged correctly, which is #185 and #2942.

## Spec references

- ISO 14289-1:2014 (PDF/UA-1), 7.18.1 and 7.18.5: annotations, and links in particular, have an alternate description in their `Contents` entry.
- ISO 32000-1:2008, 12.5.2 (`Contents` of annotations) and 14.9.3 (Alternate Descriptions): the `Alt` entry of a structure element replaces its content for assistive technologies.
- WCAG 2.2, success criterion 2.4.4 (Link Purpose, In Context).
- HTML-AAM / Accessible Name and Description Computation 1.2: `aria-label` takes precedence over the content of the element.

## Before / after

`/Contents` of the annotation and `/Alt` of the `/Link` element, for the example above plus a text link, a text link with `aria-label` and a link without any name:

| Link | `/Contents` before | `/Contents` after | `/Alt` after |
|---|---|---|---|
| text "the example site" | `https://example.org/` | `the example site` | none |
| text "1" (note call) | `note` | `1` | none |
| text "report", `aria-label="Annual report, PDF, 2 MB"` | `https://example.org/report.pdf` | `Annual report, PDF, 2 MB` | same |
| empty, `aria-label` (ORCID) | `https://orcid.org/0000-0002-1825-0097` | `ORCID profile of Jane Doe` | same |
| empty, `title` (licence) | `https://creativecommons.org/licenses/by/4.0/` | `CC BY 4.0` | same |
| empty, no name | `https://example.org/nameless` | `https://example.org/nameless` | none |
| empty, `aria-label` (back link) | `call` | `Back to the call` | same |

Before the change, no `/Link` element has `/Alt`.

The rendering is unchanged: identical pixels at 150 and 300 dpi (pypdfium2), and veraPDF `--flavour ua1` passes before and after.
